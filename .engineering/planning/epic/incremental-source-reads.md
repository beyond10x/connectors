## Operator requirements

Implement the approved fresh, multi-source brain plan. Collection polls at five minutes for chat, issue tracking and code hosting and fifteen minutes for documentation. Model launches have a durable USD 25 calendar-day budget in Europe/Berlin; reserve before launch and reconcile actual costs, exposing in-flight overruns. Discover additional permitted units hourly from evidence of activity within thirty days; never override paused/excluded units. Direct messages remain unrepresentable and private chat enrollment remains explicit. Provider reads go through connectors only. All entity state writes use the kernel; model proposals are tool-free, fully covered, revision-checked and independently receipted. Source failures are visible and isolated. Public engine/connector surfaces name no adopter or personal identity.

## Completion checks

Offline repository gates and deterministic recovery/compatibility cases pass. A bounded live pilot is a separate integration step, at most USD 5 within the daily budget. Existing source releases are not rewritten and no historical privacy migration is authorized by this work. The coordinator records every planning write and review; implementors write source, specifications and tests only.

## Acceptance

Given a configured read grant, a previously unavailable incremental issue, page or repository activity read becomes discoverable and invocable through the governed operation catalog, yielding stable item identities and a complete bounded pagination result without any new grant.
