## Outcome

`connectors connections connect <instance> --credential-file <google client.json>` (and `repair`)
opens Google consent in the browser and stores `{client_id, client_secret, refresh_token}` for an
`oauth2_refresh` connection. Decision: `architecture-decision-record:oauth-material-as-static-entry`.

## Design (verified against code 2026-09-30)

- No CLI flag change: `cli.yaml` and `apps/connectors-cli-contract` are generated by the pinned
  ESS tool (`crates/connectors-build/src/cli.rs:9-24`). The existing `--credential-file` source
  is reused.
- `apps/connectors/src/local/session.rs`: after `owner::Client::begin` (`:183-196`) returns the
  capture, if the profile carries `acquisition` (added by `story:catalog-oauth2-refresh-profile`)
  and the file parses as Google's installed-client JSON
  (`{"installed":{"client_id","client_secret","auth_uri","token_uri","redirect_uris"}}`), run the
  flow and submit the triple instead of the file bytes; any other file, or a profile without
  `acquisition`, passes through unchanged. The authorize URL, token URL and scopes come from
  `profile.acquisition`; the client file's `auth_uri` and `token_uri` must equal them, else refused.
  The profile's field names must equal the triple, else `ProtectedEntryUnavailable`.
- The flow runs inside the owner's 300 s capture window
  (`crates/connectors-host/src/local/owner/transport.rs:370`), because the profile is known only
  after `begin` (a cached bootstrap may be absent on first connect,
  `apps/connectors/src/local/owner.rs:198-205`). The flow's own timeout is 240 s, so it fails
  before the window closes; the guide says to rerun when consent took longer.
- The file stays subject to the owner-only mode check
  (`crates/connectors-host/src/local/protected.rs:110-124`); the guide tells the user to `chmod 600`
  Google's download.
- New `crates/connectors-host/src/local/oauth.rs`: PKCE S256 verifier (43–128 characters from a CSPRNG), `state`
  (random, compared in constant time), loopback listener on `127.0.0.1:0` with redirect
  `http://127.0.0.1:<port>`, authorize URL with `response_type=code`, `access_type=offline`,
  `prompt=consent`, `code_challenge_method=S256`, scopes from `profile.acquisition.scopes` plus
  `openid`; code exchange by the form POST from `story:catalog-oauth2-refresh-profile`.
- The authorize URL is written to `/dev/tty`, falling back to stderr: ordinary output is buffered
  until exit (`apps/connectors/src/main.rs:43-47`). The accept loop polls with a timeout (default
  300 s) and honours `protected::cancellation()` (`protected.rs:52,92-98`).
- The listener answers exactly one request on the redirect path; a wrong `state`, an `error=`
  parameter, or a second request is refused and the flow fails without storing anything.
- Contract: add the "OAuth-acquired non-rotating" `static_entry` variant to
  `contracts/auth/acquisition/v1alpha1/semantics.md` (row at `:74`); amend
  `crates/connectors-host/src/local/registry.rs:60-61` and `docs/local-connection-registry.md:121`.
- Guide: new `docs/catalog-google-oauth.md` (its own file, so no provider story shares it), with
  sections "Create the Google OAuth client", "Connect with OAuth", "Repair" and "Testing-mode
  expiry"; each provider guide links to it.

## Acceptance

- `crates/connectors-host` unit tests: `pkce_challenge_matches_rfc7636_appendix_b` (the RFC 7636
  Appendix B verifier/challenge pair), `state_mismatch_refused`, `error_redirect_refused`,
  `second_request_refused`, `timeout_stores_nothing`, `client_file_uri_mismatch_refused`.
- `adapters/catalog/tests/local_runtime/cli_journey.rs` gains `oauth_connect_journey`: the
  production CLI connects against a fixture authorize/token host (a test hook follows the authorize
  URL instead of a browser), the connection becomes ready, and `operations invoke` succeeds with
  the fixture access token.
- The same file gains `oauth_repair_journey`: after the token host answers `invalid_grant`, invoke
  reports `repair_connection`; `connections repair` with the client file runs the flow again, and
  the next invoke succeeds with a new fixture access token.
- A non-Google `--credential-file` connects exactly as before (existing journeys unchanged).
- `rg -n "OAuth-acquired non-rotating" contracts/auth/acquisition/v1alpha1/semantics.md
  docs/local-connection-registry.md crates/connectors-host/src/local/registry.rs` prints at least
  one line per file, and `rg -n "never OAuth or refresh" crates/connectors-host/src/local/registry.rs
  docs/local-connection-registry.md` prints nothing.
- `docs/catalog-google-oauth.md` exists with the four section headings above.
- `profile_field_mismatch_refused`: a capture whose profile fields are not exactly
  `{client_id, client_secret, refresh_token}` fails `ProtectedEntryUnavailable` and stores nothing.
- `cancellation_stores_nothing`: an interrupt during the accept loop ends the flow and stores nothing.

Live evidence is `story:catalog-google-live-deck-read`'s.

## Out of scope

The coordinator flow and trusted UI of `auth.acquisition/v1alpha1`; device flow; sharing one grant
across connections.
