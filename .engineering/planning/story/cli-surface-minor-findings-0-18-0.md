## Observed
Found by the black-box CLI surface test of release 0.18.0 on 2026-09-30 (raw output under the tester's sandbox, outside the repository).
- D6: `setup check` reports the `metadata` prerequisite with `next_action: check_configuration` even when `ready`
  (apps/connectors/src/local.rs:253); with no metadata database, reads answer `metadata_unavailable` and no
  command initialises state for an existing config (semantics.md:204-207).
- D7: an unknown adapter alias answers `not_found` at stage `admission` on 7 commands and `configuration` on 17
  (semantics.md:474-477).
- D8: `completions bash --output json` prints the raw script (semantics.md:156).
- D9: top-level `--help` differs from help.txt (short layout and an extra "Explicit service commands" block,
  apps/connectors/src/local.rs:33).
- D10: semantics.md:430 says an unknown flag is `invalid_input`; semantics.md:159-160 and the binary say `cli_parse`.
- D11: `operations list --limit=0` answers `description_unavailable` before bounds are checked.
- D12: GitLab `per_page` and Confluence `limit` declare `string|integer|boolean`, so `true` passes the host check.
## Acceptance
- Each item is fixed or answered in the contract, one line per item in the change's CHANGELOG entry.

## Split (coordinator, 2026-09-30)

D11 moved to story:list-commands-page-with-a-cursor, D9 to story:legacy-commands-parse-like-the-contract, D12 to
story:catalog-parameters-declare-their-type, D6b to story:setup-initialises-missing-state. This story keeps:
- D6a: `apps/connectors/src/local.rs:253` reports `next_action: none` for a `ready` metadata prerequisite.
- D7: an unknown alias answers stage `admission` everywhere (`local.rs:309` says `configuration`), matching
  semantics.md:474-477.
- D8: `completions` emits the raw script whatever `--output` says; the runtime is generated by the ESS CLI generator
  (`apps/connectors-cli-contract/src/runtime.rs:627-639`), so the contract text at semantics.md:156 states that.
- D10: semantics.md:430 says an unknown flag is `cli_parse`, as :159-160 and the binary do.

## Added from the ESS design review of the CLI domain (coordinator, 2026-09-30), contract text only

- Parser and input failures: the contract states the `ess-cli/1` codes (`cli_parse`, `cli_input`, `cli_source`,
  `cli_dynamic_input`, empty data, exit 2) and removes `invalid_input` for them at semantics.md:430, :433 and C05.
- Precedence: an operation id the adapter does not expose answers `not_found` before any grant check.
- The error table gains rows for `stale_cursor` (stage `observation`, `retry_explicitly`) and for a connect whose
  acquisition failed before publication (the owner's code at stage `dispatch`, `retry_explicitly`).
- One selector bound: 128 UTF-8 bytes (semantics.md:300 says 256, :459 says 128; the host enforces 128).
- semantics.md:40-41 sanctions the `ConnectionListCursor` record as it does `LocalRuntimeRecord`.
