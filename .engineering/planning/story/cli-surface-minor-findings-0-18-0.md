## Observed
Found by the black-box CLI surface test of release 0.18.0 on 2026-09-30 (raw output under the tester's sandbox, outside the repository).
- D6: `setup check` reports the `metadata` prerequisite with `next_action: check_configuration` even when `ready`
  (apps/connectors/src/local.rs:253); with no metadata database, reads answer `metadata_unavailable` and no
  command initialises state for an existing config (semantics.md:204-207).
- D7: an unknown adapter alias answers `not_found` at stage `admission` on 7 commands and `configuration` on 17
  (semantics.md:474-477).
- D8: `completions bash --output json` prints the raw script (semantics.md:156).
- D9: top-level `--help` differs from help.txt (short layout and an extra "Explicit service commands" block,
  apps/connectors/src/local.rs:33).
- D10: semantics.md:430 says an unknown flag is `invalid_input`; semantics.md:159-160 and the binary say `cli_parse`.
- D11: `operations list --limit=0` answers `description_unavailable` before bounds are checked.
- D12: GitLab `per_page` and Confluence `limit` declare `string|integer|boolean`, so `true` passes the host check.
## Acceptance
- Each item is fixed or answered in the contract, one line per item in the change's CHANGELOG entry.
