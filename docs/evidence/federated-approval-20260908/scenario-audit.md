# F03 textual scenario audit

These are normative trace reviews against [delegation](../../../contracts/service/delegation.md), [operations](../../../contracts/operations/v1alpha1/semantics.md) and [wire compatibility](../../../contracts/service/compatibility.md). They are expected observations under the stated trusted facts, not executed receiver/database/provider tests. The two independent reviewers assess the source and this evidence together.

| Case | Declared facts and expected observation |
|---|---|
| S01 configured preparation | The admitted helper resolves its implicit configured connection to the leaf's stable connection/revisions; the returned subject names that resolved connection. No provider credential read, refresh, verification, reservation, spend or business dispatch occurs. |
| S02 managed preparation | An admitted explicit selector resolves at both hops to the same leaf target. Caller cannot gain management/disclosure rights by naming another connection; refusal gives no guessed subject. |
| S03 intended mutation | Helper input names a mutation in the same current descriptor. Read targets, recursive helper targets, unknown fields and unsupported mappings refuse. Event-claim support remains unavailable until its binding is specified. |
| S04 gateway subject | Preparation and invoke reconstruct identical leaf operation/connection/revisions, input digest, trusted authority and origin/route. Gateway presentation alias is not the signed business target. |
| S05 harmless presentation refresh | Old gateway revision refuses; fresh describe and deliberate resubmission can retain identical canonical subject and unexpired approval. No automatic retry or rewriting is permitted. |
| S06 route or target changed | New route revision, leaf target/configuration/connection revision or input produces a different subject. A new candidate refuses old approval; a live key with changed fingerprint conflicts within the stable gateway namespace. |
| S07 authority narrowing | Broad gateway credentials do not replace leaf policy. Receiver checks configured projection, current principal authority, optional realm and any executor binding; admitted identity mappings cannot collide across issuers. |
| S08 optional identities | Direct configured local policy may have null tenant/realm/current-authority/executor. No synthetic executor or default realm is inserted. A real executor uses its own admitted snapshot and matching stable scope identity. |
| S09 separate origins | Direct and federated subjects differ; two gateway identities differ. Reusing a signed subject across them refuses, even when friendly operation names match. |
| S10 exact transport | Valid signature with changed method/path/raw body/receiver/audience/type/algorithm/purpose does not establish correct request authority. A decodable invocation contradicting claims refuses after entry; malformed application input follows E02 invalid_input. |
| S11 describe correlation | Signed GET has an empty-body digest, all five nullable selection/correlation fields null and a fresh nonce. Private response dispatch id matches that nonce; public request_id remains null. |
| S12 nonce duplicate | First acknowledged consume can proceed only after final current-fact checks. Duplicate exact issuer/receiver/nonce refuses without disclosing an original result; another kid/path/request id cannot make it unused. |
| S13 ambiguous consume | Lost consume acknowledgement yields unavailable with no authenticated entry, spend or provider dispatch. No retry of that delivery or assumption of absence follows. |
| S14 nonce acknowledgement delay | Expiry equality, key/projection revocation, clock uncertainty or exhausted signed deadline after consume and before final entry each prevents entry. An acknowledged nonce remains consumed. Arithmetic/truth-table examples are in time-admission-audit.json; no actual suspension was executed. |
| S15 admitted delivery expires | Expiry after successful final entry does not erase an attempt. Current authority, approval validity at atomic spending and original deadline remain constraints; no fresh total budget is granted. |
| S16 retention | A nonce cannot retire until trustworthy lower >= signed exp. Capacity, restart or uncertain clock cannot evict live uniqueness. Approval tombstones have no automatic expiry; failover cannot activate divergent/empty uniqueness history. |
| S17 new approval | Leaf verifies issuer/type/audience/reference/time and complete reconstructed subject. Missing required proof is approval_required; mismatched proof is approval_refused. Current key/time/admission are rechecked at atomic spending. |
| S18 concurrent keyed candidates | After a preliminary miss, the authoritative F02 winner recheck precedes returning approval/preflight refusal. The leaf atomically prepares one attempt plus reservation; losers observe the admitted original instead of spending again. |
| S19 spent proof, exact live key | Fresh transport and current result access permit exact existing-key wait/replay before checking old approval, even if spent/expired. No second approval spend, dispatch gate or provider call occurs. |
| S20 spent proof, new candidate | After admitted disclosure and winner recheck, a known spent reference is approval_replayed. All leaf ingress shares the spend authority. One attempt cannot gain several successful redemption receipts. |
| S21 spend/gate ambiguity | Uncertain spend grants no dispatch gate. A definite spend followed by abort stays spent/not_attempted. Uncertain gate acknowledgement grants no send and follows F01 fencing/recovery; no local future supplies definite original effect knowledge. |
| S22 gateway before send | Refusal before downstream send creates no new effect, but a keyed request may name an earlier original. Omit mutation unless admitted authoritative knowledge supports classification; do not call that original not_attempted. |
| S23 gateway after send | Missing/bad correlation, invalid reply, timeout or loss after sending a mutation is outcome_unknown absent a valid definitive observation. Never reroute, resign or resend automatically. |
| S24 known leaf result | Valid applied/refused leaf outcome survives later gateway audit failure. Preserve original attempt/request/effect/replay identity, leaf source_audit and current gateway audit anchor. Recheck current disclosure before returning waited results. |
| S25 limits | Preparation uses dedicated advertised limits; it does not authorize provider work. Final invocation including its approval proof must independently fit its selected ingress limit and original remaining budget. |
| S26 cutover | One stable logical leaf, one approval uniqueness authority and one mutating route own live traffic. Copying a key or history into an independently writable receiver cannot grant a second spend/send. |

The immutable ESS receipt entities express existing ServiceConfiguration/AttemptRecord references; no synthetic commands pretend to enforce these traces. Signature primitive success, generated type shape and arithmetic truth tables each cover a narrower property than runtime conformance.
