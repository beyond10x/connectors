# Kubernetes generation options — bounded feasibility

Source audit at `26929027f85b4653d81bd9cb290a7f472cfe84e8`. No upstream fetch/pin selection, builds, implementation or model changes. This refines the earlier preflight: a public operation need not be a one-to-one generated operation if private composition is explicit.

## Recommendation

Prefer **three private existing-v2 bundles and authored public composition** over introducing a general finite-selector/mixed-coverage adapter format, subject to the source-import and continuation checks below. This is a credible smaller design, not yet proof of zero compiler changes. It avoids the established one-mapping-per-operation, mixed API-root and public enum-lowering obstacles by changing what is generated, without changing the public Kubernetes operation contract.

| Private bundle (proposed identity) | Base path | Fixed internal mappings | Public dispatch owner |
|---|---|---|---|
| `kubernetes_core` | `/api/v1` | pods list; services list; nodes list | Authored `resources.list` kind selector; `hosts.discover` enablement |
| `kubernetes_apps` | `/apis/apps/v1` | deployments list | Authored `resources.list` kind selector |
| `kubernetes_discovery` | `/apis/discovery.k8s.io/v1` | EndpointSlices resource list; EndpointSlices endpoint discovery | Authored `resources.list` kind selector; `endpoints.discover` |

These are six internal operation declarations across three immutable generation inputs, not six new public operations, installed provider instances, credential owners or services. Proposed identities satisfy the compiler's lower-case/underscore ID rule and produce distinct ESS request crates. Actual upstream operation IDs remain unselected. Public `adapters/kubernetes/spec/adapter.json` and descriptor remain the seven-operation v1 service surface; four Helm operations remain authored. No new resource lifecycle follows from this composition.

## Facts establishing feasibility

- `Spec::parse` requires a unique **local** operation/method/type and exactly one mapping per local operation, but does not require unique `upstream_operation` (`crates/connectors-spec/src/v2.rs:176-240`). Fixed private operation names satisfy this without a selector extension. `import` processes each mapping separately, records a coverage row for each, and inserts the same selected provider path/method into the retained OpenAPI document (`:291-492`). Two EndpointSlice mappings sharing the same GET therefore retain two local coverage obligations; the identical selected source operation is stored once. The two local names must generate distinct Rust method/type names.
- Each bundle has an admitted base prefix and all its full source paths lie beneath it. Render removes that prefix and emits the remaining individually encoded segments (`crates/connectors-spec/src/v2.rs:941-960`). Since current Kubernetes transport expects full API-root-relative paths (`adapters/kubernetes/src/lib.rs:340`), integration needs a private `AuthenticatedHttp` wrapper that prepends exactly its fixed trusted prefix and forwards to the **same existing** authenticated capability. It must not create another configured HTTP client, credential selection or destination authority. The SDK's object-safe capability accepts segment/query slices (`crates/connectors-sdk/src/lib.rs:71`), so this composition is supported by the current interface.
- `fields` accepts closed required strings/integers and nullable strings (`crates/connectors-spec/src/v2.rs:84-134`). Private fixed operations need namespace (where applicable), bounded integer limit and nullable cursor; they do not need the public enum-only `kind`. Public JSON Schema validation/closed kind selection remains authored. The private schema may retain validation constraints, but the importer requires **exact matching** mapped source constraints rather than proving narrower subsets (`:399-418`). Preserve public bounds in authored admission even if the internal source-shaped schema must be broader.
- Generated `runtime.rs` exposes module-local `GeneratedAdapter<B>` with crate-visible fields, separate generated `Bindings` and a descriptor verifier (`crates/connectors-spec/src/v2.rs:855-909`). It can be included in three private Rust modules in the Kubernetes crate, with three generated request-type dependencies. Call each generated `Adapter::invoke` after public validation/admission; do not only include its types or call the old handwritten request path. Each private descriptor is verified against its private handler set; the public descriptor is separately verified against its seven public handlers before configuration narrowing.
- `prepare_*`/`finish_*` are required and may retain existing namespace/admission/cursor/response/provenance logic. A private invocation's binding context must carry the **public** operation/descriptor revision, authenticated connection partition, kind and limit used by current cursor signing (`adapters/kubernetes/src/lib.rs:328-335`), not substitute private descriptor identities. Use immutable per-call/branch context or exact branch identity; no shared mutable current-operation slot. EndpointSlice resource and discovery paths deliberately preserve distinct public cursor contexts and result shaping.

## Concrete remaining obstacles — not solved by bundle splitting

1. **Optional continuation serialization.** Existing render always emits every mapped query entry; a `Binding` is a `String`, and nullable input cannot be mapped directly (`crates/connectors-spec/src/v2.rs:201-218`, `:876-891`, `:964-968`). Current Kubernetes omits `continue` when there is no admitted cursor (`adapters/kubernetes/src/lib.rs:333-337`). Six unchanged mappings cannot express that omission themselves. First establish from the selected official source/contract whether an explicit empty continuation is equivalent; do not assume it. If exact wire omission is retained, a narrowly specified private transport adaptation may omit only the prepared absent-continuation sentinel, retaining generated path/other query construction; this is an **authored query-serialization obligation**, not fully generated optional-query support. If that obligation is unacceptable, a bounded optional-query generator addition is required even with private bundles. Doubling first/continuation mappings is a different twelve-mapping design and is not smuggled into this six-mapping proposal.
2. **Actual official source forms.** Import accepts OpenAPI 3.0/3.1 only, one original source per bundle, maximum 16 MiB before selection, SHA matching and HTTPS URL containing a 40-hex revision (`crates/connectors-spec/src/v2.rs:153-173`, `:274-290`). Splitting output does not shrink a shared oversized source input. It rejects parameter `$ref`s, non-schema/external references, more than 4096 retained schema references, and unsupported mapped schema fields/formats (`:307-539`). In particular mapped `integer` with `format:int64` is currently refused; only string/date-time format is accepted (`:374-379`). No actual Kubernetes bytes have been inspected here, so presence of that format or reusable parameters is **unmeasured**, not a reported provider fact. Multiple official group documents, if available at the selected immutable revision, could fit the three sources; a locally rewritten document is not original official bytes and needs its own transparent projection contract. Do not weaken digest/reference checks to fit a chosen document.
3. **Packaging is single-bundle today.** `LocalService` carries one specification/generated root and requires its compiled adapter ID equal the packaged adapter; package then reads one generated request domain/plan and records one generation-manifest digest (`crates/connectors-build/src/main.rs:245-256`, `:394-425`, `:493`). A public seven-operation v1 descriptor plus three private generated bundles is not represented by that current declaration. The smallest credible extension is explicit Kubernetes composition in the Rust build/check path: verify the public descriptor and all three bundles, preserve all three manifests/digests, and build one public Kubernetes realization/image with honest aggregate coverage. Review whether this is an adapter-owned composition input or an explicit Rust command; do not impersonate one private bundle as the whole public service merely to make existing packaging pass. This is build/composition work even when compiler syntax remains unchanged.
4. **Aggregate coverage is new authored evidence.** None of the three compiler coverage files alone proves all public operations. A checked aggregate must account for the public three operations, all four resource-kind branches, optional host admission, both EndpointSlice consumers and the four authored Helm handlers. Missing/duplicate/wrong-target branch, changed private source/manifest or leaked private descriptor advertisement must fail the check. Decide the exact contract/evidence representation before implementation; an informal table alone must not become successful advertisement proof. If represented as a new declaration value, give it its ESS home first; do not invent runtime ownership/cardinality.

## Contrast with a new profile

| Concern | Three private v2 bundles | One finite-selector/mixed-coverage profile |
|---|---|---|
| Public kind selection | Authored, closed and independently checked | Declared selector and generated dispatch |
| Public/internal operation correspondence | Explicit aggregate composition required | Profile represents correspondence directly |
| Multiple API prefixes | Fixed capability wrappers | New source/path base semantics |
| Seven public operations / three generated | Public v1 descriptor plus private descriptors | New generated-versus-authored coverage syntax |
| Public enum | Remains public admission; absent from private fixed inputs | Typed enum lowering/selector support required |
| Source formats and optional query | Still need the measurements/decision above | Still need source support and optional-query semantics; selector alone does not fix them |
| Packaging | Three-bundle/public-realization support required | Single generated root fits current shape more closely, subject to profile-aware package checks |

The private option reduces compiler/schema ambition but moves closure proof to authored composition. It does **not** justify claiming generated public selection or entirely generated query omission. The profile option is justified only if a reusable selector/mixed-coverage contract is itself desired; this story's existing acceptance does not establish that product requirement.

## Next bounded decision

Authorize/design-review the private composition shape provisionally; then select and inspect actual immutable official source bytes for the five endpoint shapes (six local mappings), including size, exact operation IDs, parameter forms/constraints and continuation semantics. That single measurement determines whether untouched v2 import is feasible or a narrowly scoped import/query extension remains. In parallel, specify the aggregate coverage and three-bundle packaging evidence; do not begin a general selector redesign before that result.

Acceptance stays the earlier preflight's same-image direct/federated three operations, all four resource kinds, scope/cursors/provenance, optional hosts, explicit discovery-to-SQL activation and retained Helm/catalog/SQL regressions. Normal compilation uses checked-in generated bundles. No runtime or packaging acceptance has been established by this audit.
