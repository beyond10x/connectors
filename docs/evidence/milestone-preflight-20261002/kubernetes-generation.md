## Decisions required before a contract/compiler implementation lane

These are bounded Connectors-owned design decisions, not inferred accepted semantics. Record them in ESS/declaration contracts first, then project parser/schema/runtime changes.

1. **Finite mapping alternatives.** Current `RequestMapping` is one struct and `OperationDeclaration.request_mapping` is optional-single (`ess/domains/declarations.yaml:29`, `:150`); v2 requires exactly one mapping per operation (`crates/connectors-spec/src/v2.rs:136`). Proposed minimum: a closed selector on `resources.list.kind` with exactly four statically pinned branches, refusing absent/duplicate/unrecognized branches. `endpoints.discover` and `hosts.discover` remain fixed mappings. Decide the version/profile representation explicitly; do not silently loosen existing v2 or claim proposed v3 writes provide this feature.
2. **API-root representation.** Runtime reads `/api/v1/...`, `/apis/apps/v1/...`, and `/apis/discovery.k8s.io/v1/...` (`adapters/kubernetes/src/lib.rs:313`). Current single `upstream.base_path` must be non-root/non-trailing-slash, every path is beneath it, and render strips it (`crates/connectors-spec/src/v2.rs:167`, `:941`). No admitted single prefix covers these routes. Specify root-relative source paths or explicit mapping base ownership; no path escape workaround.
3. **Typed selector input.** Current `resources.list.kind` uses an enum-only JSON Schema; current `fields` only lowers its supported typed string/integer forms (`crates/connectors-spec/src/v2.rs:84`). Specify an equivalent typed enum/constraint representation and supported lowering that retains closed input validation; do not drop the enum to obtain compilation.
4. **Mixed coverage.** Kubernetes currently declares seven operations, whereas v2 maps and verifies every operation (`crates/connectors-spec/src/v2.rs:136`, `:855`; `adapters/kubernetes/src/lib.rs:49`). Proposed minimum: explicitly distinguish the three generated read dispatches from four retained authored Helm obligations, with exact aggregate handler verification before config narrowing. An alternative private three-operation generated sub-bundle requires an explicit descriptor/aggregate verification contract. Choose one; do not remove Helm advertisement or invent mappings for authored Helm paths merely to satisfy the generator.
5. **Actual upstream pin.** Select immutable official Kubernetes OpenAPI bytes, URL/revision/digest/license and actual operation IDs for the five endpoint shapes before claiming source-derived generation. Existing documentation URLs and Helm Go-source pins are not that mapping source. Current importer has one source, a 16 MiB limit and rejects unsupported parameter/source forms (`crates/connectors-spec/src/v2.rs:263`). Inspect the selected artifact before deciding whether bounded source resolution needs extension; do not assume the selected document or importer support exists. The same EndpointSlice upstream operation is intentionally consumed by two distinct local operations and needs coverage for both.

No new runtime Kubernetes-resource entity lifecycle is required merely to model immutable mapping declarations. Preserve existing owner/custody authority. Update `ess/domains/declarations.yaml` with only the chosen mapping/source/coverage representation and its unsupported-semantics notes; keep generated request ESS separate. Corresponding Connectors spec-kind schema and semantics must state closure, refusal and authored obligations before implementation.
