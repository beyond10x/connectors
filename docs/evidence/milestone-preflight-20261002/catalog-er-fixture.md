This report is the only assigned write. The existing ten logical obligations and fifteen variants remain required; this is preparation, not implementation dispatch.

## Result

A minimal test-owned observer is feasible from the pinned public Entity Runtime APIs: open the existing exact recorded authority with `RecordedProviderFacade::start`, capture `complete_snapshot`, and decode only the three entity families needed by the historical assertions. Keep ordinary exact-reference assertions on the existing mutation/audit Store APIs where possible. No production inspection export, copied compatibility database, imported replacement store or second authority is necessary.

The chmod settlement injection remains unproved and is materially less certain than the historical implementation assumed. Fresh SQLite READ_WRITE opening may fall back to read-only, host privacy checks accept 0400, and actual ER appends can use already-open pooled Eventlog handles. A failure to inject must be reported; it cannot count as a failed-settlement journey or justify deleting those assertions.

## Minimal Rust fixture algorithm

Place a narrow helper beside the catalog local-runtime journey modules, such as `recorded_state.rs`, wired only from that integration test target. Expose fixture methods returning immutable Rust facts; keep its facade private and expose no write method.

1. After production setup has created its actual state, call and drop `connectors_host::local::metadata::Metadata::inspect(state_dir)` to establish the host's existing admission/corruption checks. Then use a short-lived rusqlite READ_ONLY/NOFOLLOW connection only to read the singleton authority marker: authority_id, logical_scope, tenant and stream_identity. Require scope `connectors.local-metadata/1`, tenant equal to the recorded authority UUID, and the expected version/marker. Close that query handle before starting the facade. Reading this immutable binding is permitted; do not query legacy business rows. Never invent a UUID, provision a stream, copy the SQLite file or import anchors.
2. Deserialize the exact production definition bundle through `include_bytes!(concat!(env!("CARGO_MANIFEST_DIR"), "/../../crates/connectors-host/src/local/metadata/entity-runtime-definitions.json"))`. Check its format and entry-name/entity agreement, register every `EntityDefinition`, and run `validate_all`, as the owner does. Do not include the private production Rust module wholesale or reconstruct definitions from fixture assumptions.
3. Start one private `RecordedProviderFacade` with `EventlogRecordedStoreOwner::Sqlite { path: state_dir/metadata.sqlite3, prefix: "connectors_er", authority: marker_tuple, limits }` and a small finite queue. Select explicit finite CaptureLimits for this bounded fixture and fail visibly if exceeded; do not turn a capacity error into an empty observation. Use `CallWait::Until` and an outer test-process bound. Never call provision/import/create/execute/append/observe-operation APIs. Keep this reader open before entering permission-fault windows; reopening requires Eventlog's write-intent admission transaction and is not a safe fault-window observation strategy.
4. Each observation calls `complete_snapshot` anew; never reuse the previous terminal map as current truth. Require the expected scope and complete coverage, unique subject/entity identities and exact required fields. Preserve receipt/history coordinates when recording diagnostics. The provider supplies the snapshot; do not manufacture a CompleteSnapshot marker on a partial collection. This helper is not a replacement for the host's corruption verifier or a new whole-store assurance claim.
5. Filter terminal entities into a single immutable `RecordedFacts` value. Join attempt, key and audit facts from that **one** capture, not separate captures straddling background recovery. Reject duplicate keys, missing expected records, malformed timestamps, wrong instance/connection/operation, and unknown states. Sort deterministically by request id or exact reference only for comparison; never choose an arbitrary first/latest row in a multi-attempt test.
6. For observations outside the narrow fault window, cross-check known references with `mutations::Store::observe` and `audit::Store::observe`. Supply a NoClock that errors if used: these reads need no time or recovery authority. Cross-check only at held/quiescent stages, or explicitly allow a subsequent legitimate lifecycle transition; two separate reads are not an atomic snapshot. Do not call recover/expire/settle from an observer. The existing subprocess producer remains the sole fixture write path and prepares through the real durable Store API; capture its returned AttemptRef and flush its fixture receipt before the deliberate exit 73.
7. After use, explicitly drain/shutdown the reader and require `ShutdownOutcome::Joined { provider: Ok(()) }`. A timeout is unfinished reader retirement, not successful cleanup. Do not release/remove fixture resources while a reader is in flight. Snapshot/replay cost may exceed the historical polling cadence: retain bounded observation and production deadlines, measure runtime cost during implementation, and report inability to fit the held-response window rather than extending product deadlines.

The private helper must not retain an exclusive lifecycle lock across reads or provider barriers. Its extra SQLite handle can keep WAL sidecars alive; record that fact when evaluating permission faults. The same authority is being observed through a second handle, not recreated as a second state authority.

## Chmod injection: mechanical assessment and required runtime proof

Historical `8dac09e:adapters/gitlab/tests/local_runtime/guarded_merge.rs:529-732` waits for an explicitly held response, changes all metadata.sqlite3-prefixed files to 0400, then releases it. Modes 8/9 require known Applied/Refused with `cause.stage=attempt_store`, `cause.code=unavailable`, incomplete audit, durable Dispatching/Pending and absent settlement/expiry. Modes 10/11 withdraw disclosure admission while metadata is still writable and retain the uncertain record without claiming no effect.

Current path:

1. `mutations.rs:78-113` enters Metadata::update before settlement; the action commits only an in-memory compatibility transaction, then metadata.persist sends the ER batch. Audit::Store follows the same fresh-update pattern at audit.rs:53-80.
2. `metadata.rs:375-408,711-754` performs a fresh physical SQLite READ_WRITE open and checks pragmas/schema, then activates the ER projection. `filesystem.rs:125-165` requires regular, owner-owned, single-link, private files but **does not require owner write permission**: 0400 passes this privacy check.
3. SQLite's bundled sqlite3.h documents that SQLITE_OPEN_READWRITE can fall back to READONLY on OS permission denial (libsqlite3-sys 0.38.2 header lines 3748-3756). Therefore a successful fresh open is not proof of write capability, nor is 0400 proof that this open fails. Host validation does not test sqlite3_db_readonly.
4. `metadata/er.rs:1745` can reuse a process-pooled recorded handle; `metadata.rs:961-968` explicitly retains Eventlog handles beyond metadata operations and provider work. chmod does not revoke those descriptors. Conversely a fresh ER reopen invokes attach_inline_existing's BEGIN IMMEDIATE and could refuse. Sidecar lifetime, pooling and SQLite locking determine the actual result; source inspection does not settle it.

Required bounded runtime witness, separately for the historical modes:

- Before changing permissions, latch the selected response class immutably and demonstrate exactly one PUT and the expected 0/1 effect. Capture the exact committed attempt Dispatching, key Pending and admitted audit lacking a final observation; prove approval spend was already committed. Revoke first for modes 10/11 and retain that successful management result.
- Record which exact metadata files and modes were changed; keep an RAII restoration guard. Keep provider method/body/response counters separate from the ER observer. Release the same known response, including catalog's required postflight reads for a successful merge; preserve the known effect instead of accidentally producing guard/postflight uncertainty.
- Require the mode's precise CLI outcome, safe attempt_store cause/incomplete audit where specified, and fresh same-authority terminal facts showing Dispatching/Pending with no settlement or expiry. An observer-open failure, permission error elsewhere, missing row or generic CLI failure does not establish settlement failure.
- Restore permissions only after the response and the pre-recovery durable-state observation have completed. Then retain all historical restart/replay, spent-proof, revoked-disclosure and exact no-extra-PUT/effect assertions. The later Indeterminate/Quarantined state must refer to the original captured attempt/key.
- Run a paired unchanged-permission control using the same production binaries, provider latch and observer, demonstrating normal terminal settlement/audit. If chmod permits terminal settlement, record the injection as rejected. Do not repeatedly change more filesystem surfaces until a different failure happens and call it equivalent.

If chmod cannot establish this controlled post-effect failure, the unresolved seam is deterministic rejection of terminal mutation/audit persistence after an acknowledged dispatch, while retaining reads and known-effect disclosure. Production host cfg(test) fault fields are unavailable to a separately built CLI. That seam needs a separately reviewed correction/injection proposal before modes 8–11 can be accepted; neither direct mutation of ER tables nor a new production inspection export is authorized by this preparation.
